## Context

DEC-006 requires slicer export for both newly created and imported models. F-007 records the open format choice that blocks implementation and acceptance of REQ-009.

## Alternatives

1. Core 3MF with an explicit millimeter unit, verified in PrusaSlicer.
2. Binary STL with coordinates converted to millimeters, verified in PrusaSlicer. STL stores no unit metadata, so correct scale depends on the slicer interpreting coordinates as millimeters.

## Decision

Use Core 3MF as the sole v1 slicer export format. Export the current mesh with coordinates expressed in millimeters and explicitly declare the millimeter unit in the file. Use PrusaSlicer as the reference slicer for acceptance testing.

## Reason

Core 3MF records the unit in the file, so the intended physical scale is explicit. PrusaSlicer provides a consistent reference for verifying that the exported dimensions are preserved.

## Consequences

Update REQ-009 to specify Core 3MF and PrusaSlicer. Verify that exports from two edited models open in PrusaSlicer with the expected X, Y, and Z dimensions within the documented numerical tolerance, without manual rescaling. Use one model created in the app and one imported from a file whose source unit differs from millimeters.
