## Context

F-004 identifies a gap in the v1 workflow for both newly created and imported models. REQ-007 requires in-app geometry validation for 3D printing. The specification leaves saving editable work and exporting geometry for a slicer undefined.

## Alternatives

1. Save and reopen editable work only. Defer slicer export beyond v1.
2. Export geometry for a slicer only. Users can resume editing through reimport, with recovery limited to the geometry and data the export format preserves.

## Decision

In v1, users can save and reopen both newly created and imported models to continue editing. They can also export the current geometry of either kind of model for use in a slicer.

## Reason

Saving lets users continue editing across sessions. Exporting lets them use the current geometry in a slicer as part of the 3D-printing workflow.

## Consequences

Add separate v1 requirements for saving editable work and exporting geometry. Reopening saved work must restore the edited geometry, its units, and any explicitly pinned dimensions. Export must preserve the physical dimensions of the current geometry in one slicer-compatible format. DEC-010 selects that format: Core 3MF with coordinates in millimeters, verified in PrusaSlicer.

## Implementation evidence

REQ-008 covers editable documents. The current I-8 plan covers the Core 3MF export selected in DEC-010. Both the File menu and the toolbar use the same workspace command. REQ-009 records the export, assembly and PrusaSlicer CLI checks. Its remaining acceptance item is a PrusaSlicer GUI scale observation for each of the two checked-in exports.
