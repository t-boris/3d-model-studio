## Context

F-008 identifies a verification gap in REQ-003. The provider can interpret dimensional wording that the application does not recognize locally. If the provider omits or misstates a dimension, the proposed geometry can pass verification against the provider's returned targets even though it misses the user's requested dimension.

## Alternatives

1. Show the axes, values, and units proposed by the agent for each unrecognized dimension and ask the user to confirm or correct them. Ask the user to supply any dimension the agent omits.

## Decision

In v1, when the application cannot unambiguously extract an explicitly requested dimension from a conversational modeling request, it asks the user to restate that dimension in documented wording, such as “final span along X is 30 mm.” The application extracts each target from the user's wording and verifies the proposed geometry against those targets before applying the edit.

## Reason

Using targets extracted directly from the user's wording lets the application verify the proposed geometry independently of the agent's interpretation.

## Consequences

Update REQ-003 to document the supported dimension wording and require the application to block application of an AI edit until it has extracted every explicitly requested dimension and verified the proposed geometry against those targets. Acceptance tests must cover a proposal that matches the agent's interpretation but has an unresolved user-specified dimension, and a reformulated request whose proposal passes only when it meets the locally extracted targets.
