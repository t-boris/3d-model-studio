## Finding

The required modeling workflows establish no product-level boundary for what geometry or project context an agent may access or receive. This matters for imported models that contain confidential designs, and for selection edits where the selected faces may be only a small part of the document.

> Each of the three integrations supports conversational model creation, revision, and edits targeting selected faces.

## Possible interpretations

- The integration may share the full active model as context for an AI request.
- A selection edit shares only the relevant geometry by default, with user authorization for broader context.

## Resolution

For creation, the agent receives the description and draft geometry. For a whole-model edit, it can access the active model. A selection edit starts with the selected faces and boundary geometry. If the agent needs other parts, the app identifies the parts, explains the reason, and requests operation-specific approval. See DEC-007.

## Implementation evidence

The approved context rule is implemented in ModelingOperation. Tests/run-provider-checks.sh captured outgoing inputs for each provider and checked specific additional face approval, refusal, expiry, and the unchanged target. DEC-007 records the geometry and lifecycle evidence. Live authenticated acceptance remains pending.

## Current plan I-4 evidence

Tests/SelectionChecks.swift verifies occurrence labels and exact wire payloads on Bambu Studio, OrcaSlicer and repeated-occurrence assemblies, across each scripted route. Requests for additional faces show the actual face IDs and user-facing reason. Approved geometry is limited to those faces and their referenced vertices. Refusal explains why the request ended and expires prior approval. Assembly metadata and occurrence labels stay local.

## I-4 re-verification

The named repeated-block fixture in 8e0925f verifies that identical part names are distinguished by component path during read review. For every scripted provider the test compares the complete initial and approved JSON bodies, including each face’s corners and each vertex’s coordinates. The human-readable part name stays out of the provider input. The scene groups keep the original target distinct from the faces awaiting read approval.
