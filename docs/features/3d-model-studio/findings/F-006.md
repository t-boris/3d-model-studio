## Finding

The required modeling workflows establish no product-level boundary for what geometry or project context an agent may access or receive. This matters for imported models that contain confidential designs, and for selection edits where the selected faces may be only a small part of the document.

> Each of the three integrations supports conversational model creation, revision, and edits targeting selected faces.

## Possible interpretations

- The integration may share the full active model as context for an AI request.
- A selection edit shares only the relevant geometry by default, with user authorization for broader context.

## Resolution

При создании агент получает описание и геометрию создаваемой модели. При правке всей модели доступна активная модель целиком. При правке выделения агент сначала получает выбранные грани и геометрию на их границе. Если нужны другие части модели, приложение показывает, какие именно и зачем, и запрашивает разрешение на текущую операцию. — see DEC-007.

## Implementation evidence

The approved context rule is implemented in ModelingOperation. Tests/run-provider-checks.sh captured outgoing inputs for each provider and checked specific additional face approval, refusal, expiry, and the unchanged target. DEC-007 records the geometry and lifecycle evidence. Live authenticated acceptance remains pending.
