## Finding

The provider setup guide requires Docker Desktop, locally built images and credentials passed to the app through its launch environment. The native macOS requirement does not establish whether this developer setup is acceptable for the v1 audience. That choice changes the installation, credential setup and release acceptance requirements for all three mandatory integrations.

> Install and start Docker Desktop on the Mac. Prepare each desired runtime image once from the repository root.

## Possible interpretations

- Выпустить v1 для пользователей, готовых установить Docker, собрать образы и передать ключи через окружение запуска.
- Выпустить v1 как приложение, в котором пользователь может настроить агентов без сборки образов и запуска из подготовленного окружения.

## Resolution

Пользователь устанавливает приложение, открывает его из Finder и подключает всех трёх агентов через интерфейс. Приложение само подготавливает нужные компоненты. — see DEC-013.

## Current plan I-5 evidence

The source-level Docker and launch-environment setup gap is addressed. Settings stages and verifies the native runtime, prompts for the provider key, checks access to the selected model and offers retry, reinstall and disconnect. Local doubles exercised those paths for all three providers. The original clean-Mac release acceptance remains outstanding.
