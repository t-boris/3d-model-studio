## Finding

When this finding was raised, the provider setup guide required Docker Desktop, locally built images and launch-environment credentials. The native macOS requirement left the intended v1 installation experience open. The excerpt below records the former guide.

> Install and start Docker Desktop on the Mac. Prepare each desired runtime image once from the repository root.

## Possible interpretations

- Выпустить v1 для пользователей, готовых установить Docker, собрать образы и передать ключи через окружение запуска.
- Выпустить v1 как приложение, в котором пользователь может настроить агентов без сборки образов и запуска из подготовленного окружения.

## Resolution

Пользователь устанавливает приложение, открывает его из Finder и подключает всех трёх агентов через интерфейс. Приложение само подготавливает нужные компоненты. — see DEC-013.

## Current plan I-5 evidence

DEC-013 resolved the setup choice. The current guide directs users to Settings, where the app provisions the chosen native runtime and checks access to the selected model. The packaged Release installer passed offline checks for all three providers on arm64 and x86_64 archive selections. Clean-Mac installation, Finder launch, live authentication and one applied live modeling operation with each provider remain pending.
