## Statement

In v1, integrate Codex, Claude, and Antigravity as configurable background agents for conversational modeling, with agent and model selection in settings. Apply the same geometry access rules to all three integrations. For model creation, the agent receives the user's description and the geometry of the model being created. For whole-model edits, the agent may access the entire active model. For selection edits, the agent initially receives only the selected faces and geometry along their boundary. The application identifies any additional parts requested, explains why they are needed, and withholds access until the user approves access to those specific parts for the current operation. Approval expires when the operation ends. If the user declines, the agent continues with the available geometry or explains why it cannot proceed. Access approval leaves the authorized edit boundary defined under F-005 in REQ-005 unchanged.

## Acceptance Criteria

- [x] Settings allow users to select Codex, Claude, or Antigravity as the active background agent.
- [x] Settings allow users to select a model supported by the active agent.
- [x] Subsequent conversational modeling requests use the selected agent and model.
- [x] Each of the three integrations supports conversational model creation, revision, and edits targeting selected faces.
- [x] For model creation, each integration receives the user's description and the geometry of the model being created.
- [x] For whole-model edits, each integration may access the entire active model.
- [x] At the start of a selection edit, each integration receives only the selected faces and geometry along their boundary.
- [x] Before granting access to additional geometry in a selection edit, the application identifies the specific parts requested, explains why they are needed, and asks the user to approve access for the current operation.
- [x] Each integration is denied access to additional geometry until the user approves access to those specific parts.
- [x] Approval to access additional geometry expires when the current operation ends.
- [x] If the user declines access to additional geometry, the agent continues with the available geometry or explains why it cannot proceed.
- [x] Granting access to additional geometry leaves the authorized edit boundary defined under F-005 in REQ-005 unchanged.

## Implementation evidence

The native workspace and Settings route each workflow to Codex CLI, Claude Code or the Antigravity SDK. Tests/run-provider-checks.sh exercised creation, draft continuation, whole-model revision and selected-face edits on every route with scripted replies. Each route preserved its selected target after approved disclosure and required separate confirmation for changes outside it. Interactive use and credential-dependent service acceptance remain pending. See [provider-specific evidence](../../../../Providers/README.md).
