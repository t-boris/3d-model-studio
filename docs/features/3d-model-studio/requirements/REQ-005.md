## Statement

Allow conversational AI edits to target explicitly selected faces. Apply the same selection-edit geometry access rules to Codex, Claude, and Antigravity. Initially provide the active agent with only the selected faces and geometry along their boundary. Before granting access to any additional geometry, identify the specific parts requested, explain why they are needed, and ask the user to approve access for the current operation. Withhold those parts until the user approves access, share only the approved parts, and expire approval when the operation ends. If the user declines, the agent continues with the available geometry or explains why it cannot proceed. Approval to access additional geometry leaves the authorized edit boundary unchanged.

In v1, before applying any proposed selection-based AI edit that changes an unselected face or its topology, show the user the affected region and obtain explicit confirmation for the proposed changes outside the selection. This rule applies when the changes are needed to keep neighboring geometry connected and when moving a shared vertex changes an unselected face. If the user declines confirmation, leave the model unchanged.

Verify dimensions requested for the current edit before applying it, including when the user confirms changes outside the selection. Explicit dimensions apply only to the edit that sets them by default. Users can explicitly pin dimensions on new or imported models to preserve them across subsequent manual and AI edits until they change or unpin them. Check pinned dimensions before applying a proposed AI edit, including when the user confirms changes outside the selection, and reject edits that violate them, identifying the conflicting dimension. Use the documented numerical tolerance for both requested and pinned dimension checks.

## Acceptance Criteria

- [ ] A user can select one or more faces.
- [ ] A user can issue an AI instruction referring to the selection.
- [ ] Codex, Claude, and Antigravity each use the selected faces as the target of the requested edit.
- [ ] At the start of a selection edit, the application provides the active agent with only the selected faces and geometry along their boundary.
- [ ] Before sharing any additional geometry, the application identifies the specific parts requested, explains why they are needed, and asks the user to approve access for the current operation.
- [ ] The application withholds additional geometry until the user approves access and then shares only the specific parts approved for the current operation.
- [ ] Approval to access additional geometry expires when the current operation ends.
- [ ] If the user declines access, the agent continues with the available geometry or explains why it cannot proceed.
- [ ] Approval to access additional geometry leaves the authorized edit boundary unchanged.
- [ ] If a proposed selection-based AI edit changes any unselected face or its topology, the application shows the affected region before requesting explicit confirmation.
- [ ] The application applies a proposed selection-based AI edit that changes any unselected face or its topology only after the user explicitly confirms the proposed changes outside the selection.
- [ ] Changes to unselected faces or their topology needed to keep neighboring geometry connected still require the application to show the affected region and obtain explicit confirmation.
- [ ] A proposed edit that moves a shared vertex and thereby changes an unselected face requires the application to show the affected region and obtain explicit confirmation.
- [ ] If the user declines confirmation for the proposed changes outside the selection, the model remains unchanged.
- [ ] Before applying an AI edit, including an edit the user confirmed outside the selection, the application verifies that the proposed geometry meets each dimension explicitly requested for that edit within the documented numerical tolerance.
- [ ] An explicit dimension applies only to the edit that sets it by default.
- [ ] The user can explicitly pin a dimension on a new or imported model.
- [ ] A pinned dimension remains in force until the user changes or unpins it.
- [ ] The user can explicitly unpin a dimension so that subsequent edits no longer enforce it as a pinned constraint.
- [ ] Before applying each subsequent AI edit, including an edit the user confirmed outside the selection, the application checks the proposed geometry against every pinned dimension using the documented numerical tolerance.
- [ ] If a proposed AI edit violates a pinned dimension, the application rejects the edit, leaves the geometry unchanged, and identifies the conflicting dimension.
- [ ] The resulting geometry change appears in the viewport after the edit is applied.
