## Statement

Allow conversational AI edits to target explicitly selected faces. Apply the same selection-edit geometry access rules to Codex, Claude, and Antigravity. Initially provide the active agent with only the selected faces and geometry along their boundary. Before granting access to additional geometry, identify the specific parts requested, explain why they are needed, and ask the user to approve access for the current operation. Withhold those parts until approval, share only the approved parts, and expire approval when the operation ends. If the user declines access, the agent continues with the available geometry or explains why it cannot proceed. Approval to access additional geometry leaves the authorized edit boundary unchanged.

In v1, compare each candidate locally with the original full indexed mesh using the face IDs selected at the start of the operation. Include incident unselected faces in the affected region when their shared vertices move or their vertex or edge connectivity changes, including changes needed to keep neighboring geometry connected. Show removed faces on the original mesh and added faces on the candidate mesh. Before applying a candidate that changes any unselected face or its topology or adds any face, show the affected region and obtain explicit confirmation for those changes. New faces require review because they have no selected face ID in the original mesh. Confirmation applies only to the candidate shown. If the user declines, leave the model unchanged.

When the application cannot unambiguously extract an explicitly requested dimension from the user's wording, ask the user to restate it in documented wording, such as “final span along X is 30 mm.” Block application until the application has locally extracted every explicitly requested dimension from the user's wording and verified the candidate against those targets. By default, an explicit dimension applies only to the edit that sets it. Users can explicitly pin dimensions on new or imported models to preserve them across subsequent manual and AI edits until they change or unpin them. At commit, check the candidate's whole-model spans against the locally extracted targets for the current edit and all current pinned dimensions, including pins added during review. Use the documented numerical tolerance for both checks, including when the user has confirmed changes outside the selection. If the candidate violates a pinned dimension, reject the edit, leave the geometry unchanged, and identify the conflicting dimension. Display the committed geometry in the viewport.

## Acceptance Criteria

- [ ] The user can select one or more faces.
- [ ] The user can issue a conversational instruction referring to the selected faces.
- [x] Codex, Claude, and Antigravity each use the selected faces as the target of the requested edit.
- [x] At the start of a selection edit, the application gives the active agent only the selected faces and geometry along their boundary.
- [x] Before sharing additional geometry, the application identifies the specific parts requested, explains why they are needed, and asks the user to approve access for the current operation.
- [x] The application withholds additional geometry until the user approves access, then shares only the approved parts for the current operation.
- [x] Approval to access additional geometry expires when the current operation ends.
- [x] If the user declines access, the agent continues with the available geometry or explains why it cannot proceed.
- [x] Approving access to additional geometry leaves the authorized edit boundary unchanged.
- [x] The application determines the affected region locally by comparing the candidate with the original full indexed mesh and using the face IDs selected at the start of the operation.
- [x] The affected region includes incident unselected faces when their shared vertices move or their vertex or edge connectivity changes, including changes needed to keep neighboring geometry connected.
- [x] When showing the affected region, the application displays removed faces on the original mesh and added faces on the candidate mesh.
- [x] Every new face requires review because it has no selected face ID in the original mesh.
- [x] The application shows the affected region before requesting explicit confirmation for any proposed change to an unselected face or its topology, or for any new face.
- [x] The application applies changes requiring review only after the user explicitly confirms that specific candidate. A revised candidate with changes requiring review needs its own confirmation.
- [x] If the user declines confirmation, the model remains unchanged.
- [x] If the application cannot unambiguously extract an explicitly requested dimension from the user's wording, it asks the user to restate that dimension in documented wording, such as “final span along X is 30 mm.”
- [x] A proposal that matches the agent's interpretation is blocked while any explicitly requested dimension remains unresolved, even if the user confirms changes outside the selection.
- [x] After the user restates an unresolved dimension, the application extracts the target locally. A candidate whose whole-model span falls outside the documented numerical tolerance is blocked, and a candidate within tolerance passes that dimension check.
- [x] At commit, the application verifies that the candidate's whole-model spans meet every locally extracted target for the current edit within the documented numerical tolerance, including after the user confirms changes outside the selection.
- [x] By default, an explicitly requested dimension applies only to the edit that sets it.
- [x] The user can explicitly pin a dimension on a new or imported model.
- [x] A pinned dimension remains in force across subsequent manual and AI edits until the user changes or unpins it.
- [x] The user can explicitly unpin a dimension so that subsequent edits no longer enforce it as a pinned constraint.
- [x] At commit, the application checks the candidate's whole-model spans against every current pinned dimension within the documented numerical tolerance, including pins added during review and pins affected by changes the user confirmed outside the selection.
- [x] If a proposed AI edit violates a pinned dimension, the application rejects the edit, leaves the geometry unchanged, and identifies the conflicting dimension.
- [x] After the application commits the edit, the resulting geometry appears in the viewport.

## I-3 implementation evidence

Workspace.commit accepts a proposal against its original model and checks the current pins before publishing the geometry. The interpreted checks reject a proposal when a pin was added after the proposal snapshot.

## Selection proposal review

Compare the candidate with the original full indexed mesh locally, using the face IDs picked at the start of the operation. Include incident unselected triangles when their shared points move or their vertex or edge connectivity changes. Show removed faces on the original mesh and additions on the candidate. A new face has no selected identifier in the original mesh and requires review. The edit confirmation belongs to this candidate only. At commit, validate the user's operation targets and the workspace's current pins against the candidate's whole-model spans.
